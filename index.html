문제 해결 기록

증상진짜 원인
뒤로가기가 홈이 아니라 방금 본 화면으로 돌아감'목록으로'가 push라 같은 화면이 스택에 쌓임

개별 버그로 고치지 않고 화면 이동을 세 갈래로 나눠 앱 전체에 적용했습니다. 내려가기는 push로 돌아올 자리를 남기고, 올라가기와 갈아타기는 스택에 있으면 그 화면까지 되감고, 뒤로와 닫기는 돌아갈 곳이 없으면 홈으로 보냅니다.

직접 뒤로가기를 호출하던 코드가 공용 함수 하나로 모였습니다.

Android 빌드만 45분에 잘림캐시 설정이 node_modules 전체를 압축 업로드

같은 커밋의 iOS 빌드는 8분에 끝났습니다. 두 번 재 보니 45분 09초, 45분 12초로 같은 지점에서 멈췄고, 로그는 '캐시 저장 중'에서 끝나 있었습니다. 빌드 본체는 이미 성공한 뒤였습니다. 캐시 설정을 제거하고 배포 문서에 근거를 남겼습니다.

기획과 다른 구현 18건 때문에 pre-push가 매번 실패늘 빨간 게이트는 건너뛰기를 습관으로 만듦

알려진 차이는 '실패 예상'으로 표시하고 사유를 한 줄씩 달았습니다. 구현이 맞춰지면 러너가 '예상과 달리 통과'로 알려 주고, 그때 표시를 지웁니다. 시간 초과까지 통과로 알리던 문제도 찾아 통과와 판정 불능을 구분했습니다.

문제 해결 기록

증상진짜 원인
일부 기기에 푸시가 영구히 오지 않음서버 자격증명 오류를 '토큰 무효'로 분류해 정상 기기의 토큰을 삭제

발송부가 외부 푸시 서비스의 오류를 '재시도'와 '토큰 삭제' 두 갈래로만 나누고 있었습니다. iOS 인증 키가 잘못됐을 때 오는 오류가 삭제 쪽에 들어가 있어서, 서버 설정 하나가 틀린 동안 정상 기기의 토큰이 하나씩 지워졌습니다.

해당 오류를 서버 조치가 필요한 영구 오류로 다시 분류하고 인증 키를 교체했습니다.

코드 스플리팅을 켜자 모든 라우트가 빈 화면컴포넌트 참조가 끊어짐. 유닛 테스트는 전부 통과

가상 DOM에서는 렌더가 성공한 것처럼 보였고, 실제 브라우저로 띄웠을 때만 흰 화면이 드러났습니다. 헤드리스 브라우저로 라우트를 순회해 실측하고서야 찾았습니다. 이후 화면이 보이는지는 실제 브라우저에서 확인합니다.

로그인 전에 초대장을 열어야 함인증 없는 API는 식별자를 바꿔 가며 타인 정보를 긁어 갈 수 있음

딥링크에는 암호화된 페이로드만 싣고, 서버가 복호화한 값으로만 조회하게 했습니다. 응답 전용 DTO를 분리해 개인정보를 마스킹하고, 게이트웨이의 인증 예외를 해당 엔드포인트로만 한정했습니다.

문제 해결 기록

증상진짜 원인
온보딩 중에 앱을 끄면 처음부터 다시 시작됨진행 상태가 메모리에만 있어 재진입 시 복원할 근거가 없음

온보딩 단계 식별자와 입력값을 AsyncStorage에 단계마다 저장하고, 앱 재시작 시 저장된 상태를 확인해 해당 페이지로 라우팅하도록 분기를 넣었습니다. 완료 시 명시적으로 지워 다음 사용자에게 영향이 가지 않도록 했습니다.

모달이 화면마다 생겼다 사라지며 중복 구현됨모달 상태가 각 화면 로컬에 있어 교차 전환 시 겹치거나 사라짐

Zustand에 전역 모달 큐를 두어 열기·닫기·우선순위를 한 곳에서 처리했습니다. 호출부는 종류와 페이로드만 넘기면 되고, 레이아웃·접근성 처리는 공용 컴포넌트가 담당합니다.

문제 해결 기록

증상진짜 원인
기기를 바꾸거나 앱을 지우면 가계부 데이터가 사라짐데이터가 로컬 SQLite에만 있어 디바이스 수명과 데이터 수명이 같아짐

Supabase로 옮겨 사용자별 데이터를 클라우드에 두고, 로그인 후 디바이스가 바뀌어도 동일하게 조회·수정되도록 했습니다. 전환 과정에서 로컬 스키마를 원격 테이블과 매핑하고, 네트워크 실패 시 로컬 큐에 쌓았다가 재전송하는 경로를 추가했습니다.

7일 미사용이면 Supabase 인스턴스가 정지됨이용자 수가 적어 자연 트래픽으로는 활성 조건을 못 채움

GitHub Actions에 매일 정해진 시간에 가벼운 조회 쿼리를 돌리는 워크플로를 추가해 추가 비용 없이 활성 상태를 유지했습니다. 로그에서 실행 성공 여부를 주기적으로 확인하는 절차를 함께 두었습니다.
